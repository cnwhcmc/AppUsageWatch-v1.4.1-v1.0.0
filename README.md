# 使用日志（AppUsageWatch）

Android 应用使用时间监控与日志记录工具。

- **包名**：`com.usagewatch.app`
- **应用名**：使用日志
- **版本**：1.4.1（versionCode 18）
- **minSdk**：25（Android 7.1.1，低版本可用）
- **targetSdk / compileSdk**：34
- **技术栈**：Kotlin + 原生 SQLite + 系统 UsageStats + FileObserver（运行时依赖仅 AppCompat/Shizuku 官方 API，安装包约 830KB）
- **显示**：日志按时间**倒序（最新在上）**；时间精确到秒；日志行**长按可复制**；不足 1 秒的瞬时段自动过滤不显示

---

## 一、功能清单

### 核心功能
1. **监控总开关**：开启才开始记录并在后台保活；关闭则立即停止服务、开机不再自启（彻底关停）。总开关开启时自动申请通知/存储等运行时权限；每次回到应用都同步服务状态（幂等拉起），授权后无需重开应用即可开始记录。
2. **前台使用时间线**：通过系统官方 `UsageStatsManager.queryEvents` 秒级事件，记录"某应用几点几分开始运行、持续到几点"，可跨天按时间线回查（如"今天 9:00–10:00 抖音在前台"）。
3. **后台运行估算**：按天聚合、跨天结算——当日活跃窗口 − 前台段落之和 = 当日后台估算。估算值在 detail 中标注"估算"；不足 60 秒不输出，避免噪音。
4. **文件事件监控**：两种范围可切换——
   - **指定目录**（默认）：Download / DCIM / Pictures / Documents / Movies / Music 六个公共目录，可在设置中**多选增减、并手动添加自定义目录**（相对名或绝对路径），每个目录递归 2 层；
   - **整个公共存储（全盘）**：授予存储/所有文件访问权限后，递归监控公共存储下所有目录（跳过 Android/LOST.DIR 等系统目录），**新建目录动态补监听**，受系统 inotify 上限保护（最多约 6000 个目录，超出部分跳过并记录）。
   - 记录"时间 + 路径 + 事件类型"（创建 / 删除 / 移动 / 写入）。范围或目录变更后，后台服务在下一采样周期自动生效（≤30 秒），无需重启应用。
5. **日志双写**：事件同时写入 SQLite（查询用）与按天滚动的文本日志（`app_yyyyMMdd.log`，程序员可读）。
6. **服务状态可查**：设置页实时显示"采集服务运行中 · 最后采集时间"，直接判断服务是否真的在跑、是否有心跳数据。

### 附加能力
5. **日志保留天数可配**（默认 7 天，可 1/3/7/30 天或永久），每日自动清理过期数据。
6. **双显示模式**：
   - 图形模式（默认）：时间线 + 应用小图标 + 应用名，普通人可读；
   - 纯代码模式（设置中开启）：无图标、输出原始字段，供程序员/自动化解析。
7. **导出与分享**：将数据库导出为文本，经系统分享面板发给任意应用。
8. **权限引导**：首次进入自动弹引导对话框，逐项引导特殊权限。
9. **图标零重复加载**：应用图标来自本机系统包管理（**非网络下载**），同一应用图标只解析一次并缓存复用（LruCache），滚动/重复记录行不会重复加载；解析失败自动回退系统默认图标，不影响列表。
10. **全应用弹性**：任何一步非致命异常都不会拖垮应用——采集、入库、文件监控、UI 渲染全部异常隔离并记录；全局未捕获异常也会写入当天日志文件（`[ERROR]` 前缀）供用户导出排查。

### 能力增强（可选，不阻塞普通模式）
9. **三档权限自适应**：
   - `NORMAL`：仅普通权限，功能完整可用（保底）；
   - `SHELL`：**Shizuku 已激活且本应用已授权**（仅安装不算）或进程以 shell 身份运行时启用；
   - `ROOT`：检测到 `su`（PATH 或 KernelSU/APatch 等常见安装路径）或进程以 root 身份运行时启用；
   - 检测只读、有异常兜底、不主动执行 su 授权弹窗；检测失败一律回退普通模式。
10. **Shell/Root 真实增益（不是拿权限没区别）**：
   - **实时前台校准**：每轮用 `dumpsys` 解析真实前台应用，修正系统事件延迟/丢失导致的时间线错位；
   - **后台估算"进程存活确认"**：每轮用 `ps` 获取真实进程列表，后台估算条目标注进程是否存活（普通模式无此能力，不显示标注）；
   - 失败自动静默降级，不影响任何普通功能。
11. **省电切换**：设置中可将权限模式切为"普通模式（省电）"，此时不做任何提权探测与增强命令，最省电；切回"自动"即恢复。
12. **版本日志**：设置页可查看全部历史版本及大致修改内容。
13. **保活机制**：前台服务（dataSync 类型）+ `START_STICKY` + 开机自启（BOOT_COMPLETED）+ 省电白名单引导 + 自启动管理引导。
14. **无障碍交叉验证**（默认关闭）：仅监听窗口切换事件，读取当前前台包名，用于与 UsageStats 结果比对；因可能与辅助按钮冲突，仅作为手动可选开关。

## 二、界面结构

底部三个 Tab：

| Tab | 内容 |
|---|---|
| **应用日志** | 线性时间线（**最新在上**）：`时间  应用图标+名称  事件`；顶部有应用筛选（全部/指定包名）与时间范围筛选；**顶部"记录"开关即唯一总开关**（开=开始记录并后台保活，关=彻底停止） |
| **文件日志** | 线性时间线（最新在上）：`时间  事件类型  文件路径`；同样支持筛选 |
| **设置** | 权限与配置（见下表） |

> 时间显示精确到秒；任意日志行长按即可复制整行文本到剪贴板；**设置页所有行的值实时刷新**（修改后立即生效，从系统设置返回后自动更新授权状态）。

### 设置项
| 设置 | 说明 | 默认 |
|---|---|---|
| 权限引导 | 使用情况访问（必需）/ **存储访问**（Android 11+ 走"所有文件访问"，低版本申请存储权限）/ 电池优化 / 自启动 / 通知 | 逐项按钮 |
| 显示模式 | 图形模式 / 纯代码模式 | 图形 |
| 保留天数 | 1 / 3 / 7 / 30 / 永久(0) | 7 |
| 采样间隔 | 10s / 30s / 1min / 5min | 30s |
| 监控范围 | 指定目录 / 整个公共存储（全盘） | 指定目录 |
| 监控目录 | 6 个默认目录多选 + **添加自定义目录** | 全部默认 |
| 后台估算 | 开启/关闭"后台运行时长（估算）"输出 | 开 |
| 无障碍开关 | 手动开启/关闭交叉验证服务 | 关 |
| 存储清理 | 立即删除过期日志 | — |
| 导出日志 | 分享导出 | — |
| 能力状态 | 当前模式（普通/Shell/Root）与说明 | 自动 |

## 三、运行逻辑（数据流）

```
启动/开机（总开关开启时）
  └─ MonitoringService（前台服务，串行 HandlerThread；onResume 幂等拉起、总开关关闭拒绝运行）
       ├─ UsageCollector：每采样间隔增量拉取 UsageStats 事件
       │    ├─ 首次游标初始化为最近 2 小时（不查全量历史，防内存溢出）
       │    └─ 游标回退 15 分钟 buffer 兜住进行中段的起点；按时间戳去重
       ├─ TimelineProcessor：事件 → 前台开始/结束 + 按天聚合后台估算（跨天结算）
       │    ├─ 锁屏/灭屏/关机事件 → 强制结束所有进行中的前台段
       │    └─ 后台 = 当日活跃窗口 − 前台段之和（标注"估算"）
       ├─ FileEventCollector：FileObserver(指定目录深2 / 全盘递归+上限保护, 按路径节流) + MediaStore 兜底
       │    ├─ 监控范围/目录变更 → 服务下一 tick 自动重启监听（≤30s 生效）
       │    └─ 记录 时间+路径+类型（创建/删除/移动/写入）
       └─ LogRepository：写 SQLite + 写按天日志文件（事务批量）
            └─ 每日清理：删除保留天数之前的库记录与日志文件
                    ↓
UI 读取（MainActivity，后台线程查询）
   ├─ 总开关：控制服务启停与开机自启
   ├─ 应用/文件 双 Tab 线性时间线（图形/代码双模式渲染）
   └─ 设置页：服务状态（运行/心跳）、权限逐项状态与跳转
```

关键口径：
- 前台数据来源为系统官方事件流（秒级精度，非轮询猜测）；
- 后台时长**估算**属性明确标注，避免误导；
- 所有采集在服务内串行执行，异常隔离，单模块失败不影响其他模块；
- 文件事件不归属到应用（普通权限无法可靠归因，root 审计日志归属为 POC 项）。

## 四、权限体系

### 必需（普通模式保底）
| 权限 | 用途 |
|---|---|
| `PACKAGE_USAGE_STATS`（特殊） | 前台时间线数据来源，需用户在"使用情况访问"中手动开启 |
| 存储（按版本分层） | 文件事件监控 |
| 通知 | 前台服务常驻通知（Android 13+ 需运行时申请） |
| `FOREGROUND_SERVICE` + `dataSync` | 常驻采集 |
| `RECEIVE_BOOT_COMPLETED` | 开机自启 |

### 存储分层口径
| API 版本 | 权限方案 |
|---|---|
| 25–28 | `WRITE/READ_EXTERNAL_STORAGE` 全盘访问 |
| 29 | `requestLegacyExternalStorage` 传统存储模式 |
| 30–32 | `MANAGE_EXTERNAL_STORAGE`（所有文件访问；侧载不受商店政策限制） |
| 33+ | `READ_MEDIA_*` 媒体权限（侧载可另开所有文件访问） |

### 保活（引导用户开启，不强制）
- 自启动管理（厂商设置页深链接）
- 省电白名单（`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`）

### 可选增强（默认关闭）
- 无障碍服务：交叉验证用，与辅助按钮冲突风险，仅手动开启
- Shell（Shizuku）/ Root：自动探测，探测到即增强

## 五、日志格式

落盘日志位于 `/sdcard/Android/data/com.usagewatch.app/files/logs/`，按天命名 `app_yyyyMMdd.log`，内容恒为**原始字段**（与显示模式无关）：

```
2026-09-11 09:00:03 | com.ss.android.ugc.aweme | 1 | 前台开始
2026-09-11 10:00:01 | com.ss.android.ugc.aweme | 2 | 前台结束，持续 3598s
2026-09-11 10:00:05 | com.ss.android.ugc.aweme | 3 | 后台运行（估算）212s
2026-09-11 11:23:11 | /storage/emulated/0/Download/a.pdf | 10 | 写入 a.pdf
2026-09-11 11:23:12 | /storage/emulated/0/Download/b.pdf | 12 | 创建 b.pdf
```

类型码：`1` 前台开始 · `2` 前台结束 · `3` 后台运行（估算）· `10` 文件写入 · `11` 文件移动 · `12` 文件创建 · `13` 文件删除 · `14` 媒体库变化

## 六、构建方法

环境要求（本机已就绪）：
- JDK 17（AGP 8.2.2 要求）
- Android SDK（platform 34 + build-tools 34.0.0）
- Gradle wrapper 8.6（已生成）

```bash
export JAVA_HOME=/home/user/android-build-tools/jdk-17.0.20.1+1
export ANDROID_HOME=/home/user/android-build-tools/android-sdk
./gradlew assembleDebug          # 调试包（debug 自动签名）
./gradlew assembleRelease        # 发布包（已配置混淆 + keystore 签名）
```

- release 签名：`keystore/usagewatch.jks` + `keystore.properties`（含私钥密码）。**私钥丢失无法找回**，只能以同一签名覆盖升级；**切勿将 keystore 与密码公开分发**。
- 产物：`app/build/outputs/apk/debug/app-debug.apk`、`app/build/outputs/apk/release/app-release.apk`

## 九、已知限制（如实声明）

- 后台运行时长是**估算值**，不是系统精确数据（普通应用拿不到系统级精确后台统计）。
- 文件事件只能覆盖公共目录且**无法可靠归因到应用**（归因需 root 审计日志，POC 验证中）。
- 系统事件流偶尔有丢事件（厂商魔改 ROM），以"前台结束缺失时按灭屏/锁屏/下一开始补齐"策略兜底，极小概率时段重叠。
- 杀后台/厂商激进策略下，前台服务可能被系统停止；已用保活组合尽量缓解，但不能保证 100% 常驻。
